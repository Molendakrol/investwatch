Architektura

Cztery niezależne usługi, start jedną komendą

Źródła

Strony WWW, YouTube, eksporty postów, Meta Ad Library API, rejestr UKNF

→

Worker (scraper)

Kolejka zadań, rotacja User-Agent i proxy, robots.txt, ponowienia, limit zapytań

Python · httpx · BeautifulSoup

→

Analyzer

Czyszczenie HTML, embeddingi, SimHash, reguły M1/M2/M3, opcjonalnie lokalny LLM

Python · FastAPI · Ollama (Gemma)

→

API

Baza, kolejka, harmonogram, WebSocket, magazyn kopii dowodowych (SHA-256)

FastAPI · PostgreSQL

→

Panel

Filtry, wykresy, statusy spraw, kalibracja, alerty na żywo

React · TypeScript · Tailwind

Skalowalność

Worker i analyzer są bezstanowe — dokładamy kopie: --scale worker=4.

Otwartość

Nowe źródło = jeden kolektor. Nowa reguła = jedna funkcja. Mocniejszy model = podmiana jednej funkcji.

On-premise

Docker Compose, wyłącznie open source, bez płatnych API. LLM działa lokalnie.

Moduły 1 i 3

M1

Firma z rejestru + kod polecający lub „współpraca” + publikuje ktoś inny niż firma.

Doradztwo bez zezwolenia

Frazy doradcze, personalizacja, odpłatność, podobieństwo do ofert doradczych + brak w rejestrze UKNF.

Raport: podmiot, status w rejestrze, oferta, URL. CSV.

Silnik pobierania danych

Scraper, który działa uczciwie i stabilnie

  • Kolejka zadań z priorytetami i ponawianiem; harmonogram co 30 min.
  • Rotacja User-Agent i puli proxy, limit zapytań na host.
  • Respektuje robots.txt — Facebook, X, LinkedIn: analiza wklejonej treści.
  • Kolektory: WWW, YouTube, eksporty postów, Meta Ad Library API, rejestr UKNF.
  • Wykrywanie duplikatów (SimHash) i zmian treści.

Bezpieczeństwo i proces

Bezpieczny łańcuch dostaw, przejrzysty proces z AI

Bezpieczeństwo

  • npm audit: 0 i pip-audit: 0 podatności (Starlette podniesiony po skanie).
  • Sekrety wyłącznie w pliku .env.
  • Ochrona przed SSRF — adresy sieci wewnętrznej blokowane.
  • Pobrany HTML nigdy nie jest wykonywany w panelu — podgląd jako tekst.
  • Kopia dowodowa każdego materiału z sumą SHA-256.
  • Kontenery uruchamiane jako użytkownik bez uprawnień administratora.

Proces wytwarzania z asystentem AI

  • Specyfikacja i załączniki UKNF → plan → implementacja „od danych do UI”.
  • Bramki: TypeScript, build, test jakości na korpusie z etykietami, audyty zależności.
  • Weryfikacja w przeglądarce (desktop i telefon) przed każdym oddaniem.
  • Opisane w docs/PROCES_AI.md, reguły dla asystenta w CLAUDE.md.
  • Przykład: test wykazał pełność 70% → analiza błędów → 90% / 100%.

Uczciwie o ograniczeniach

Co jest prototypem — i jak to rozwinąć

Ograniczenia dziś

  • Facebook, Instagram, TikTok, X, LinkedIn — bez logowania tylko wklejona treść lub oficjalne API.
  • Kalibracja na korpusie syntetycznym (fikcyjne podmioty).
  • Reguła 8 (telefon) — symulacja na podstawie CSS, bez renderowania.
  • Ocena to podpowiedź dla analityka, nie rozstrzygnięcie.

Następne kroki z UKNF

  • Etykiety na rzeczywistych próbkach UKNF → kalibracja progów na prawdziwych danych.
  • Oficjalne API platform (Meta Ad Library z tokenem, TikTok Research API).
  • Renderowanie stron (Playwright) dla reguł prezentacyjnych.
  • Model językowy dostrojony do polskich materiałów finansowych.
